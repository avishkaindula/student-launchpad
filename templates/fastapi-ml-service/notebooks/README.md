# Notebooks

Notebooks are the right place to explore: look at the data, try features, compare models, make plots. They are the wrong place for code the API depends on, because nobody can re-run them reliably or test them. Once something works (a cleaning step, a feature, the model you picked), move it into `training/train.py` (or a new module in `training/`) and import it back into your notebook: run `%cd ..` in the first cell so paths match the project root, then `from training.train import load_data, build_pipeline`. Clear outputs before committing (`Kernel → Restart & Clear Output`) to keep diffs readable, and never commit large datasets; keep them in `data/raw/`, which is git-ignored. To use Jupyter with this project's environment, run `uv run --with jupyter jupyter lab` from the project root.
